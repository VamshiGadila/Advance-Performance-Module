2. AUTHENTICATION & PUBLIC APIS
================================================================================

--------------------------------------------------------------------------------
[API-01] USER LOGIN
--------------------------------------------------------------------------------
Method:      POST
Endpoint:    /api/auth/login
Auth:        Public (None)

Request Body (JSON):
  - email                 [String, Required]  Registered user email
  - password              [String, Required]  Plaintext password

Sample Request:
{
  "email": "hr@ascend.local",
  "password": "Password1"
}

Response Fields (200 OK):
  - token                 [String]   Signed JWT Bearer token
  - id                    [Long]     User ID primary key
  - employeeCode          [String]   Code (e.g. HR001, MGR007, EMP001)
  - name                  [String]   User's full name
  - email                 [String]   User's email
  - role                  [String]   Role (HR, MANAGER, EMPLOYEE)
  - departmentId          [Long]     Assigned Department ID
  - departmentName        [String]   Assigned Department name

--------------------------------------------------------------------------------
[API-02] REGISTER EMPLOYEE (SIGNUP)
--------------------------------------------------------------------------------
Method:      POST
Endpoint:    /api/auth/signup
Auth:        Public (None)

Request Body (JSON):
  - name                  [String,  Required] 2-100 chars, legal name
  - email                 [String,  Required] Unique valid email format
  - password              [String,  Required] Min 8 chars, 1 uppercase, 1 lowercase, 1 digit
  - confirmPassword       [String,  Required] Must match password
  - departmentId          [Long,    Required] Existing Department ID
  - skill                 [String,  Optional] Technical skills (e.g. "Java, Spring Boot")
  - domain                [String,  Optional] Business domain (e.g. "Engineering")
  - location              [String,  Optional] Location (e.g. "Hyderabad")
  - experienceYears       [Integer, Optional] Years of experience (>= 0)

Sample Request:
{
  "name": "David Miller",
  "email": "david.miller@ascend.local",
  "password": "Password1",
  "confirmPassword": "Password1",
  "departmentId": 1,
  "skill": "Java, Spring Boot, React",
  "domain": "Engineering",
  "location": "Hyderabad",
  "experienceYears": 4
}

Response Fields (201 Created):
  - id                    [Long]     Auto-generated User ID
  - employeeCode          [String]   Auto-generated unique code (e.g. EMP020)
  - name                  [String]   Full name
  - email                 [String]   Registered email
  - role                  [String]   "EMPLOYEE"
  - departmentId          [Long]     Department ID
  - createdAt             [String]   ISO Timestamp

[API-21] ALLOCATE GOAL TO EMPLOYEE
--------------------------------------------------------------------------------
Method:      POST
Endpoint:    /api/manager/goals
Auth:        Bearer Token (MANAGER)

Request Body (JSON):
  - employeeId            [Long,       Required] Assigned direct report Employee ID
  - cycleId               [Long,       Required] Active Cycle ID
  - goalType              [GoalType,   Required] "OKR" or "KPI"
  - goalScope             [GoalScope,  Optional] "INDIVIDUAL" (default), "DEPARTMENT", "COMPANY"
  - parentGoalId          [Long,       Optional] Parent goal ID for alignment
  - title                 [String,     Required] 3-200 chars, objective title
  - description           [String,     Optional] Max 1000 chars
  - target                [String,     Optional] Max 500 chars, metric target
  - weight                [BigDecimal, Required] 1.00 to 100.00 (Total sum cannot exceed 100.00%)
  - dueDate               [LocalDate,  Required] ISO format (yyyy-MM-dd)

Sample Request:
{
  "employeeId": 4,
  "cycleId": 1,
  "goalType": "OKR",
  "goalScope": "INDIVIDUAL",
  "title": "Migrate Monolith Auth to Microservices OAuth2",
  "description": "Implement Spring Security 6 with JWT tokens and Redis session store",
  "target": "Zero downtime and 99.9% authentication uptime",
  "weight": 35.00,
  "dueDate": "2026-11-30"
}

Response Fields (201 Created):
  - id                    [Long]       Goal ID
  - cycleId               [Long]       Cycle ID
  - employeeId            [Long]       Employee ID
  - employeeName          [String]     Employee Name
  - managerId             [Long]       Manager ID
  - managerName           [String]     Manager Name
  - goalType              [String]     "OKR" / "KPI"
  - goalScope             [String]     "INDIVIDUAL"
  - title                 [String]     Title
  - description           [String]     Description
  - target                [String]     Target
  - weight                [BigDecimal] 35.00
  - dueDate               [LocalDate]  2026-11-30
  - status                [String]     "PENDING_ACCEPTANCE"
  - progress              [Integer]    0
  - employeeAccepted      [Boolean]    false
  - modificationRequested [Boolean]    false
  - createdAt             [String]     ISO Timestamp

[API-32] UPDATE GOAL PROGRESS (0% TO 100%)
--------------------------------------------------------------------------------
Method:      PATCH
Endpoint:    /api/employee/goals/{goalId}/progress
Auth:        Bearer Token (EMPLOYEE)
Path Param:  goalId (Long, Required)

Request Body (JSON):
  - progress              [Integer, Required] 0 to 100 percentage
  - comment               [String,  Optional] Notes / remarks

Sample Request:
{
  "progress": 75,
  "comment": "OAuth2 filters and token validation services completed"
}

Status Transitions:
  - progress = 100        -> Status becomes "COMPLETED" (completedAt recorded)
  - 0 < progress < 100    -> Status becomes "IN_PROGRESS"

6. ADVANCED DYNAMIC SEARCH & FILTERING APIS
================================================================================

--------------------------------------------------------------------------------
[API-35] DYNAMIC EMPLOYEE SEARCH (PAGINATED & SORTED)
--------------------------------------------------------------------------------
Method:      GET
Endpoint:    /api/employees/search
Auth:        Bearer Token (Any Authenticated User)

Query Parameters:
  - search                [String,  Optional] Global keyword across name/email/code/skills
  - name                  [String,  Optional] Filter by partial name
  - email                 [String,  Optional] Filter by partial email
  - employeeCode          [String,  Optional] Exact code (e.g. EMP001)
  - departmentId          [Long,    Optional] Department ID
  - role                  [Role,    Optional] HR, MANAGER, EMPLOYEE
  - skill                 [String,  Optional] Skill substring (e.g. "Java")
  - domain                [String,  Optional] Domain (e.g. "Engineering")
  - location              [String,  Optional] Location (e.g. "Hyderabad")
  - minExperience         [Integer, Optional] Minimum years of experience
  - maxExperience         [Integer, Optional] Maximum years of experience
  - active                [Boolean, Optional] Filter by active status (default: true)
  - page                  [Integer, Optional] 0-based page index (default: 0)
  - size                  [Integer, Optional] Page size (1 to 100, default: 10)
  - sortBy                [String,  Optional] Field name (default: "name")
                                              Allowed: id, name, email, employeeCode,
                                              experienceYears, location, skill, domain
  - direction             [String,  Optional] "asc" (default) or "desc"

Response Fields (PagedResponse<EmployeeResponse>):
  - content               [List]    Matching EmployeeResponse objects for page
  - page                  [Integer] Current page (0-based)
  - size                  [Integer] Page size
  - totalElements         [Long]    Total records matching criteria in database
  - totalPages            [Integer] Total pages available
  - first                 [Boolean] true if on first page
  - last                  [Boolean] true if on last page
